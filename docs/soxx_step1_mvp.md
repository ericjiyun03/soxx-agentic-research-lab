# SOXX/SOXL Step 1 Deterministic MVP

## Goal

Implement the first layer of the SOXX/SOXL research system without agents, MCP, LangGraph, or LangSmith.

This MVP answers:

```text
Can deterministic code pull market data, build basic point-in-time features, train simple models, run a walk-forward backtest, and write auditable artifacts?
```

## What This Step Includes

- Pull daily OHLCV data for `SOXX`, `SOXL`, and `SMH`
- Cache raw price CSVs locally
- Build price/volatility/momentum features using only data available through each row's date
- Define forward targets for SOXX 1-day and 5-day return/direction
- Train simple deterministic models:
  - logistic regression for direction
  - ridge regression for forward return
- Run walk-forward evaluation
- Use bounded walk-forward settings by default so the no-dependency implementation runs quickly
- Generate a latest as-of forecast
- Save feature, prediction, metric, and forecast artifacts

## What This Step Does Not Include

- LLM agents
- MCP servers
- LangGraph orchestration
- LangSmith tracing
- news/event extraction
- SEC/fundamental features
- production-grade trading logic

Those come after the deterministic base is working.

## Run

From the repository root:

```bash
cd SOXX_agentic
```

Use live Yahoo chart API data:

```bash
python3 scripts/run_soxx_mvp.py --config configs/soxx_mvp.json
```

If the local Python install has certificate issues, use:

```bash
python3 scripts/run_soxx_mvp.py --config configs/soxx_mvp.json --insecure-ssl
```

Use deterministic sample data for a local smoke test:

```bash
python3 scripts/run_soxx_mvp.py --config configs/soxx_mvp.json --sample-data --output-dir artifacts/soxx_mvp_sample
```

## Full Runtime Flow

The only file you run directly is:

```text
scripts/run_soxx_mvp.py
```

Everything else is imported and called by that script.

### 1. `scripts/run_soxx_mvp.py` starts

This is the Step 1 orchestrator.

It imports helper functions from:

```text
soxx_mvp/backtest.py
soxx_mvp/data.py
soxx_mvp/features.py
soxx_mvp/io_utils.py
```

Then it parses command-line arguments such as:

```text
--config
--output-dir
--sample-data
--refresh
--insecure-ssl
```

### 2. `soxx_mvp/io_utils.py` loads the config

`run_soxx_mvp.py` calls:

```python
config = read_json(args.config)
```

Input:

```text
configs/soxx_mvp.json
```

Output:

```text
Python config dictionary
```

The config controls:

```text
tickers
date range
horizons
training window
prediction stride
maximum backtest predictions
long/short thresholds
transaction cost assumption
logistic regression settings
ridge regression settings
```

The config is currently hand-written. It is not generated by an agent or another script.

### 3. `soxx_mvp/data.py` pulls or generates prices

If using live data, `run_soxx_mvp.py` calls:

```python
prices = load_or_fetch_prices(...)
```

That calls:

```python
fetch_yahoo_daily(...)
```

Inputs:

```text
tickers: SOXX, SOXL, SMH
start_date
end_date
cache_dir
```

Output:

```python
prices = {
    "SOXX": [Bar, Bar, ...],
    "SOXL": [Bar, Bar, ...],
    "SMH": [Bar, Bar, ...]
}
```

It also writes cached CSVs to:

```text
data/market_cache/
```

If using `--sample-data`, the script calls:

```python
generate_sample_prices(...)
```

instead of pulling Yahoo data.

### 4. `soxx_mvp/features.py` builds feature rows

`run_soxx_mvp.py` calls:

```python
rows = build_feature_rows(prices, ...)
```

Input:

```text
price bars from data.py
```

Output:

```text
model-ready feature rows
```

Each row contains:

```text
date
SOXX return features
SOXL return features
SMH return features
volatility features
volume z-score features
SOXX/SMH spread feature
SOXL realized leverage feature
SOXX drawdown feature
forward target returns
forward target directions
```

Important: `features.py` does not dynamically discover features yet. It is a static, hand-written feature builder.

It always builds these feature families:

```text
for SOXX, SOXL, SMH:
  ret_1d
  ret_5d
  ret_20d
  vol_20d
  volume_z20

cross features:
  soxx_smh_ret_spread_5d
  soxl_leverage_realized_5d
  soxx_drawdown_20d

targets:
  target_return_1d
  target_direction_1d
  target_return_5d
  target_direction_5d
```

Later, `run_soxx_mvp.py` writes these rows to:

```text
features.csv
```

### 5. `soxx_mvp/backtest.py` runs walk-forward backtests

For each horizon in the config, currently `1` and `5`, `run_soxx_mvp.py` calls:

```python
predictions, metrics = run_walkforward(rows, horizon=1, ...)
predictions, metrics = run_walkforward(rows, horizon=5, ...)
```

Inputs:

```text
feature rows from features.py
model settings from configs/soxx_mvp.json
backtest settings from configs/soxx_mvp.json
```

Inside `run_walkforward`, the code repeatedly:

```text
selects historical training rows
extracts model feature columns
extracts target labels
trains logistic and ridge models
predicts the next eligible row
records prediction and strategy return
```

### 6. `soxx_mvp/features.py` provides model input columns

Inside `backtest.py`, the code calls:

```python
columns = feature_columns()
```

This returns the fixed list of approved model input columns.

Examples:

```text
soxx_ret_1d
soxx_ret_5d
soxx_ret_20d
soxx_vol_20d
soxx_volume_z20
soxl_ret_5d
smh_ret_5d
soxx_smh_ret_spread_5d
soxl_leverage_realized_5d
soxx_drawdown_20d
```

So the current Step 1 setup is:

```text
feature definitions: hand-coded
feature selection: hand-coded
model config: hand-written JSON
agent involvement: none
```

### 7. `soxx_mvp/models.py` trains the models

Inside each walk-forward step, `backtest.py` calls:

```python
logistic = fit_logistic(...)
ridge = fit_ridge(...)
```

Inputs:

```text
x_train: historical feature rows
y_direction: future SOXX up/down label
y_return: future SOXX return
```

Outputs:

```text
logistic model: predicts probability SOXX goes up
ridge model: predicts expected SOXX return
```

Then the code calls:

```python
prob_up = logistic.predict_proba_one(x_current)
pred_return = ridge.predict_one(x_current)
```

### 8. `soxx_mvp/backtest.py` creates prediction rows

For each prediction date, the backtest records:

```text
date
horizon
train_start_date
train_end_date
n_train
actual_return
actual_direction
prob_up
pred_direction
pred_return
position
strategy_return
buy_hold_return
```

The `position` field is based on the configured probability thresholds:

```text
prob_up >= long_threshold -> long
prob_up <= short_threshold -> short
otherwise -> flat
```

Then `run_soxx_mvp.py` writes:

```text
predictions_h1.csv
predictions_h5.csv
```

### 9. `soxx_mvp/metrics.py` scores predictions

At the end of each horizon, `backtest.py` calls:

```python
metrics = score_predictions(predictions)
```

That scoring uses functions from `metrics.py`:

```text
accuracy
precision
recall
Brier score
RMSE
MAE
return IC
Sharpe
max drawdown
```

Output:

```text
metrics dictionary
```

Then `run_soxx_mvp.py` writes:

```text
metrics.json
```

### 10. `soxx_mvp/backtest.py` creates the latest forecast

After backtesting, `run_soxx_mvp.py` calls:

```python
latest_forecast(rows, horizon=1, ...)
latest_forecast(rows, horizon=5, ...)
```

This trains on the latest available historical window and predicts from the final feature row.

Example output:

```json
{
  "as_of_date": "2026-05-07",
  "horizon": 5,
  "prob_up": 0.70,
  "pred_direction": 1,
  "pred_return": 0.031,
  "naive_soxl_expected_return": 0.093
}
```

Then `run_soxx_mvp.py` writes:

```text
latest_forecast.json
```

### 11. `soxx_mvp/io_utils.py` writes artifacts

Finally, `run_soxx_mvp.py` writes:

```text
features.csv
predictions_h1.csv
predictions_h5.csv
metrics.json
latest_forecast.json
run_config.json
```

## Modeling Contract

The agentic system can later propose features and configs, but this MVP keeps model execution deterministic:

```text
agent proposes experiment -> code validates feature columns -> code trains model -> code evaluates walk-forward -> code writes metrics
```

The LLM should not directly produce predictions.
